# 外部问题提交工作流

将讨论中需要外部确认的问题整理并登记到问题清单。AI Agent 按此流程执行。

---

## 流程步骤

### 1. 整理问题

在 Story 创建或评审过程中，识别以下类型的问题：

| 问题类别 | 说明 | 示例 |
|----------|------|------|
| 产品需求 | 需求描述缺失或模糊，需要产品经理澄清 | 原型中某 Tab 无内容设计 |
| 原型问题 | 原型交互与预期不符，需修正 | 弹窗显示错误的表单 |
| 业务规则 | 业务逻辑不明确，影响数据模型设计 | 字段范围、状态流转规则未定义 |
| 技术确认 | 技术方案需要业务方确认 | 是否需要支持某个功能特性 |

### 2. 合并与精简

根据用户在对话中确认需要提交的问题，进行合并精简：

- **合并同类问题**：同一模块/功能的多个子问题合并为一条，用编号列出子问题
- **控制数量**：不必每个小问题独立一条，相关联的问题合并提交
- **问题描述结构化**：
  - 第一行：`【问题性质/紧急程度】` 标签
  - 主体：分小节描述，每个子问题用 ①②③ 编号
  - 末尾：说明对开发的影响

### 3. 拉取最新文件（避免冲突）

在修改 Excel 前，先拉取父仓库最新代码以确保问题清单文件是最新的：

```bash
cd property-management-system && git pull origin main
```

**注意**：问题清单 Excel 是多人共享文件，如果不先 pull 直接修改，可能覆盖他人新增的问题记录。

### 4. 写入问题清单 Excel

**目标文件**：`docs/物业管理系统_问题清单_v1.1.xlsx`（工作表：`问题清单`）

#### 3.1 字段填写规范

| 列 | 字段名 | 填写规则 |
|----|--------|----------|
| A | 问题ID | 顺序递增，格式 `Q-NNN`（在最后一条已填写的记录之后递增） |
| B | 提出方 | 固定填 `供应商` |
| C | 提出日期 | 当天日期，格式 `YYYY-MM-DD` |
| D | 问题类别 | `产品需求` / `原型问题` / `业务规则` / `技术确认` |
| E | 模块/功能 | 层级格式，如 `项目管理 / 项目详情 / 查验移交` |
| F | 问题描述 | 结构化描述（见上一步的格式） |
| G | 截图 | 如有相关截图则说明，一般留空 |
| H | 优先级 | `高`（阻断开发）/ `中`（影响但不阻断）/ `低`（优化建议） |
| I | 期望回复日期 | 高优先级：3个工作日内；中优先级：5个工作日内 |
| J | 甲方回复/决策 | 留空（等待回复） |
| K | 回复日期 | 留空 |
| L | 状态 | 固定填 `待确认` |
| M | 处理措施/行动 | 留空 |
| N | 影响评估 | 说明对哪个 Story/功能的影响 |
| O | 确认人 | 留空 |
| P | 关闭日期 | 留空 |
| Q | 备注 | 关联的 Epic/Story 编号；如有默认开发方案则注明 |

#### 3.2 写入方式

使用 openpyxl 写入，**复制上一条记录的样式**：

```python
from openpyxl import load_workbook
from openpyxl.utils import get_column_letter
from copy import copy

wb = load_workbook('docs/物业管理系统_问题清单_v1.1.xlsx')
ws = wb['问题清单']

# 1. 找到最后一条有内容的行
# 2. 找到下一个空行作为写入位置
# 3. 从上一条记录复制单元格样式（font, fill, border, alignment, number_format）
# 4. 写入数据
# 5. 保存文件
```

**注意事项**：
- 跳过已有 ID 占位但内容为空的行（如 Q-010~Q-024 的空白行）
- 优先填充这些已有 ID 的空白行
- 如果空白行的 ID 不连续，按顺序使用

### 5. 更新 Story 文件

在对应的 Story 文件中更新"待确认问题"部分：

```markdown
## Pending Questions (阻断项)

- **Q-010**（高优先级）：查验移交交互设计确认 → 见 `docs/物业管理系统_问题清单_v1.1.xlsx`
- **Q-011**（中优先级）：项目接收 Tab 功能范围 → 见 `docs/物业管理系统_问题清单_v1.1.xlsx`
```

如问题为高优先级且阻断开发，在 Story 文件顶部或显著位置标注 `BLOCKED`。

### 6. 更新 Sprint 状态（可选）

如果问题导致 Story 无法继续开发：
- Sprint-status 保持当前状态（如 `ready-for-dev`），不推进到 `in-progress`
- 在对话中告知用户当前 Story 被阻断，等待问题回复后继续

---

## 问题回复处理

当用户告知问题已得到回复时：

1. 根据回复内容更新 Excel 中对应行：
   - **甲方回复/决策**（J列）：填写回复内容
   - **回复日期**（K列）：回复日期
   - **状态**（L列）：改为 `已确认` 或 `已关闭`
   - **处理措施/行动**（M列）：根据回复决定的行动
   - **确认人**（O列）：回复方
   - **关闭日期**（P列）：如已关闭则填写
2. 根据回复调整 Story 文件中的设计方案
3. 如阻断问题已解决，继续 Story 开发流程
