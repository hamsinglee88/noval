# 问题提交工作流

将讨论中需要外部确认的问题整理并登记到问题清单。AI Agent 按此流程执行。

---

## 流程步骤

### 1. 整理问题

在 Story 创建或评审过程中，识别以下类型的问题：

| 问题类别 | 说明 | 示例 |
|----------|------|------|
| 产品需求 | 需求描述缺失或模糊，需要产品经理澄清 | 某功能的使用场景未定义 |
| 原型/UX | 交互设计与预期不符，需修正 | 某页面的布局或交互逻辑不明确 |
| 业务规则 | 业务逻辑不明确，影响数据模型设计 | 状态流转规则、阈值未定义 |
| 技术确认 | 技术方案需要确认 | 是否需要支持某个功能特性 |

### 2. 合并与精简

根据用户在对话中确认需要提交的问题，进行合并精简：

- **合并同类问题**：同一模块/功能的多个子问题合并为一条，用编号列出子问题
- **控制数量**：不必每个小问题独立一条，相关联的问题合并提交
- **问题描述结构化**：
  - 第一行：`【问题性质/紧急程度】` 标签
  - 主体：分小节描述，每个子问题用 ①②③ 编号
  - 末尾：说明对开发的影响

### 3. 拉取最新文件（避免冲突）

在修改问题清单前，先拉取最新代码以确保文件是最新的：

```bash
git pull origin main
```

**注意**：问题清单是多人共享文件，如果不先 pull 直接修改，可能覆盖他人新增的问题记录。

### 4. 写入问题清单

**目标文件**：`design-artifacts/questions.md`（Markdown 格式）

#### 字段填写规范

```markdown
## Q-{NNN} 【优先级】问题标题

- **类别**: 产品需求 / 原型问题 / 业务规则 / 技术确认
- **模块/功能**: 层级格式，如 `风格管理 / 风格分析`
- **提出日期**: YYYY-MM-DD
- **问题描述**: 
  ① 子问题 1 描述
  ② 子问题 2 描述
- **影响评估**: 说明对哪个 Story/功能的影响
- **期望回复日期**: 高优先级 3 个工作日；中优先级 5 个工作日
- **状态**: 待确认 / 已确认 / 已关闭
- **甲方回复/决策**: （等待回复）
- **确认人**: （等待填写）
- **关闭日期**: （等待填写）
- **备注**: 关联的 Epic/Story 编号
```

#### 优先级定义

| 优先级 | 说明 | 回复期限 |
|--------|------|----------|
| 高 | 阻断开发，无法继续实现 | 3 个工作日 |
| 中 | 影响设计但可暂按假设推进 | 5 个工作日 |
| 低 | 优化建议，不影响当前开发 | 下次迭代前 |

### 5. 更新 Story 文件

在对应的 Story 文件中更新"待确认问题"部分：

```markdown
## Pending Questions (阻断项)

- **Q-001**（高优先级）：XXX 功能范围确认 → 见 `design-artifacts/questions.md`
- **Q-002**（中优先级）：XXX 交互设计确认 → 见 `design-artifacts/questions.md`
```

如问题为高优先级且阻断开发，在 Story 文件顶部或显著位置标注 `BLOCKED`。

### 6. 更新 Sprint 状态（可选）

如果问题导致 Story 无法继续开发：
- Sprint-status 保持当前状态（如 `ready-for-dev`），不推进到 `in-progress`
- 在对话中告知用户当前 Story 被阻断，等待问题回复后继续

---

## 问题回复处理

当用户告知问题已得到回复时：

1. 更新 `design-artifacts/questions.md` 中对应问题：
   - **甲方回复/决策**：填写回复内容
   - **状态**：改为 `已确认` 或 `已关闭`
   - **确认人**：回复方
   - **关闭日期**：如已关闭则填写
2. 根据回复调整 Story 文件中的设计方案
3. 如阻断问题已解决，继续 Story 开发流程
